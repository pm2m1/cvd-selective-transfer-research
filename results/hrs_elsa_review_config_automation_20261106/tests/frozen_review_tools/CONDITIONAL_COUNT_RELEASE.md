# Conditional engineering paths — no clinical count release yet

## A — Observability only

`conditional_paths.observability()` exposes the recorded diagnostic interpretation and the frozen check without changing decisions. Missing and zero remain distinct. The previously prepared error-code split is already available in the conflict-investigation package; no duplicate controller is created here. Unresolved contradictions continue to block counting.

## B — Demonstrated implementation correction

No such defect is currently established. `defect_path()` returns NOT_ESTABLISHED and NO_EXECUTION. There is no fabricated before/after corrected clinical predicate. A real correction would require an exact public specification violation, supporting protected evidence reviewed independently, a minimal isolated change and a failing/passing synthetic regression. Nothing in a worksheet frequency or higher event yield can establish that violation.

## C — UNADOPTED prospective amendment prototype

The exact conservative proposal in `conditional_paths.prospective_quarantine()` is: **if any historical W1–9 status tuple is not CONSISTENT under the existing diagnostic classification, propose quarantining the whole person from both baseline designs.** All visits and any separately supplied history evidence remain unchanged. No interval is removed, no prevalence erased, no unknown event becomes0, and no person is declared eligible by the prototype. Known missed-wave/no-Core plus inw0 alone is consistent; it does not erase the gap or certify disease-negative follow-up. Fallback ambiguity triggers proposed quarantine even with inw1.

This is a status-only synthetic policy prototype, not an adopted full count algorithm. It may disproportionately exclude older, ill, institutional, proxy, re-entering or poorly linked participants. It can reduce information and alter the estimand. It could be excessively restrictive. It has not been evaluated on real data and is not recommended merely to obtain executable counts. Independent review must justify its scope, missingness/selection implications and clinical-history consequences **before** any use. Tests preserve invented prevalent MI/stroke, unknown follow-up, death, proxy, repeated reports and re-entry evidence literally; they do not validate a new epidemiological cohort.

## Conditional release build/verification process

1. Complete independent scientific determination for every observed family, with authoritative evidence, A/B/C category and unresolved limitations. The helper never accepts a completed decision as an authorization.
2. If B is established or a fully specified C amendment is legitimately adopted, create a new public count source directory from the enumerated frozen release, preserving original artifacts. Apply only the justified rule; version protocol/configuration/runtime/source bindings explicitly. Do not edit expected historical identities.
3. Keep W6→9 primary and W4→7 comparator; preserve the incident reported MI/stroke contract unless an explicitly adopted amendment changes a stated part. Test baseline free/history positives, disputes, interval references, missed waves/re-entry, death/exit/proxy, unknown outcomes, denominators, predictor timing, duplicates and integrity. Include before/after acceptance-set comparison and justify every changed cell.
4. Verify source and release inventory, actual existing registered-source equivalence and supported CLI. Prepare new private configuration and output, new appropriate scope and **fresh interactive count authorization**. The old failed attempt and its markers/receipt remain permanent. No count CLI is invented here because no corrected release is justified yet.
5. Review actual private event/nonevent/unknown waterfalls, exclusions, follow-up coverage, feature timing and model-partition information. The old four-role capacity scenario cannot certify the training pipeline's five target roles. Scientific precision assessment must use explicit prevalence/signal/uncertainty assumptions, not a universal event-number PASS.
6. Only after acceptance may a separately permitted raw-to-canonical exporter be implemented/reviewed and used for training inputs. The source-specific HRS assumed-negative sensitivity remains labeled as such. No current outcome supports a public empirical training GO.

No code in this package builds, authorizes or executes a clinical count; all three public paths remain NO_EXECUTION until an independently justified new release exists.
