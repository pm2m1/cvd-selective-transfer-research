# Unadopted status-quarantine prototype

The executable proposal is `conditional_paths.prospective_quarantine`, described exactly in `CONDITIONAL_COUNT_RELEASE.md`. It consumes only status tuples and an optional invented history-evidence payload in synthetic tests. It returns a proposed quarantine flag while returning eligibility and outcome as unknown (`None`) and count execution as NO_EXECUTION. It is never imported by the clinical counter or review CLI.

This is category C, not a demonstrated bug fix. No authority/adoption/date/signature is assigned. Source identity, original failed output and existing scientific protocol remain untouched. It is not a complete epidemiological protocol: independent review must resolve applicability, target population and selection bias, effects on personal lifetime evidence, interval references, positive/prevalent reports, unknown follow-up, censoring and actual two-window accounting before any full implementation could be justified. Whole-person exclusion is explicit; deletion of a disputed wave is prohibited.

The prototype does not promise larger cohorts or more events. It may remove substantial information. No real frequency or outcome was examined to select it. A different supported rule requires its own prospective rationale and tests; editing an adoption string cannot activate this code on real data.
